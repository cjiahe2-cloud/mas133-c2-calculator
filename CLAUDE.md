# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A RAG chatbot for two MAS (Monetary Authority of Singapore) insurance notices: MAS 125 (Investments of Insurers) and MAS 133 (Valuation and Capital Framework for Insurers). The PDFs in `s3-rag-mas/` are embedded into a local Chroma vector store, and a LangChain agent answers questions using only the passages it retrieves, citing notice, page and paragraph. It was adapted from the sibling project `C:\dev\rag-tutor` (a CFA textbook tutor) and keeps the same architecture. There is no web search: the only source is the local PDFs.

## Commands

Uses `uv` with Python 3.14. `OPENAI_API_KEY` must be in `.env` (template: `.env.example`). Scripts call `load_env()`, which stops with a clear message if the key is missing or still the placeholder.

```
uv sync                                     # install dependencies
uv run python ingest.py --dry-run           # chunks + citation labels, no OpenAI calls (use this to check parsing)
uv run python ingest.py                     # embed new PDFs into chroma_db/ (skips notices already there)
uv run python ingest.py --rebuild "MAS 133" # re-embed one notice; bare --rebuild re-embeds all
uv run python chat.py                       # terminal chat
uv run streamlit run app.py                 # web chat
uv run python test_search.py                # retrieval check -> search_results.docx
uv run python answer_test.py                # answer check    -> answers.docx
uv run python calc_test.py                  # calculator vs MAS worked examples + hand-worked figures (free)
```

There is no test framework, linter, or CI. `calc_test.py` asserts calculator figures. `test_search.py` and `answer_test.py` are manual evaluation scripts that call the OpenAI API (they cost money) and write Word reports for a person to review.

## Architecture

Everything shared lives in the `insurance_mas_rag` package (`src/insurance_mas_rag/__init__.py`): paths, settings (`COLLECTION = "mas_notices"`, `EMBED_MODEL`, `CHAT_MODEL = "gpt-4.1-mini"`, `K = 10`), `load_env()`, `notice_name()` / `notice_version()`, `open_vectorstore()`, `citation()`, `format_chunks()`, `SYSTEM_PROMPT`, `build_agent()` and `latest_turn()`.

- **Filenames carry identity**: `<name>_<revision date>.pdf`. `notice_name()` turns the stem into `MAS 125` / `MAS 133`, and `notice_version()` takes the date after `_`.
- **Ingestion (`ingest.py`)**: per page, `page_text()` extracts text and restores Calibri glyphs that MAS 133's broken font maps turn into spaces (`GLYPH_FIX`, keyed by font + glyph id: `N`, ligatures `ti`/`fi`/`fl`/`ff`, etc.; pp.127, 136-165, 193-223). On those pages it also inserts a space at visible gaps between words. `check_spaces()` prints a WARNING (in `--dry-run` and real runs) for any other glyph that extracts as a space but isn't the font's space width, which is how a new broken font in a revised PDF shows up: identify the glyph from the surrounding words and add it to `GLYPH_FIX`. Then `clean_page()` removes the running header and page number and joins lone labels (`17.`, `(a)`) to the next line. `ParaTracker` finds paragraph numbers at line starts. It rejects table values (any `0` component), cross-references (text after the number not capitalised), list items inside multi-level numbering, and numbers that are not the current or next top-level number. It resets at each `Appendix X` page title. MAS 133's numbered `Guidelines:` boxes have their own sequence (4.4, 4.5… between paras 4.2.10 and 4.2.11; `1.`, `2.` in appendices) and are stored with a `G` prefix (`G4.4`, cited as "Guideline 4.4"). A box ends at the next paragraph number, definition line, or sub-item whose first sentence says "must"; in Appendix 3D, whose `(1)` paragraphs aren't tracked, the label falls back to the appendix alone. `segments()` gives each definition (`“term” means…`) its own piece on pages with 3+ definitions; then pieces are split with `RecursiveCharacterTextSplitter(1200, 200, add_start_index=True)`. Appendix chunks start with a context line, `[Appendix 5E: <TITLE> · F. Adjustment for Asset Concentration]` (lettered `SECTION` headings ≤60 chars not followed by a lowercase line), so table chunks match searches for their section's topic. Each chunk gets metadata `doc` (stem), `notice`, `version`, `page` (**0-based**), `appendix`, `para_start` (the paragraph in effect where the chunk starts, carried across pages) and `para_end`. Chroma needs scalar values, so missing values are `""`. IDs are `<doc>:p<page>:c<n>` (upsert).
- **Revisions**: a notice already stored under the same `doc` is skipped. If the same `notice` exists under an older `doc`, ingest warns and asks for `--rebuild`. `--rebuild` deletes by `notice`, so the old revision is removed.
- **Retrieval contract**: every consumer opens the same `chroma_db/` + `mas_notices` collection with the same embedding model. Changing `EMBED_MODEL` means deleting `chroma_db/` and re-ingesting.
- **Citations**: `citation()` builds `MAS 133 p.31, paras 4.2.13-4.2.16`, `MAS 133 p.30, para 4.2.8 to Guideline 4.5` or `MAS 133 p.129, Appendix 4A`. Pages are 1-based for users.
- **Agent**: one tool, `search_notices(query, notice=None)`, where `notice` filters on metadata. `with_context()` appends the next chunks of the same appendix when a hit says "following table(s)" (e.g. Appendix 5E para 16 → the concentration-limit tables), and the next page's first chunk when a page's last chunk ends mid-sentence (e.g. para 4.3.5.6's "less 10%" is on the next page). `build_agent(model)` takes the model name; `chat_model()` drops the temperature for reasoning models (gpt-5*, o*), which only accept the default. It uses an `InMemorySaver` checkpointer (memory per `thread_id`, lost on restart) and a `Context` dataclass. The prompt requires citations, exact quotes of "must" wording, the must/should (requirement vs guideline) distinction, and searching again to follow cross-references.
- **Calculator**: `calculator.py` (pure Python, amounts in SGD millions) computes the FX mismatch risk requirement (paras 4.3.5.3-4.3.5.7: higher of long/short net open positions less 10% Singapore / 20% offshore, × 12%), and the adjustment for asset concentration (Appendix 5E para 16; limits are % of total assets less reinsurers' share less unit reserves, with the para 17B $5m minimum; the 40% FX limit applies only to Singapore-policies funds). The FX part follows `FX_ADJUSTMENT_METHOD`, which the user chose: `"total_less_limit"` (default: once FX exposure is over the limit, adjustment = total asset value − 40% × total asset value, e.g. 100m − 40m = 60m; no para 4.1.8 recalculation) or `"excess"` (exposure over the limit, then para 4.1.8 recalculates the FX requirement excluding that excess). Other Table 2-I items always use the excess over the limit. The user's method and the 4.1.8 step are interpretations: keep the caveat that an actuary should confirm them. The prompt tells the bot to report the calculator's figures and not argue for another method. The agent's second tool, `capital_calculator` (`CalculatorInput` schema; `fund_type` defaults to "singapore": the user wants every fund treated as a Singapore-policies fund unless they say offshore, without the bot mentioning the assumption), returns `CALC_HEADER` + steps + `CALC_PASSAGES` + the notice chunks behind the steps, found by text (`CALC_SOURCES`, via `where_document $contains`) so the model quotes notice text, not calculator lines. `app.py` shows the steps in a "Calculation steps" expander. The second half of `calculator.py` computes the rest of C2 (not yet an agent tool): `equity_requirement` (Tables 4D-I/II, segment correlations 0.9 / 0.75, CCA), `interest_rate_requirement` (duration approach, Table 4E % of base yield capped at 200bp; the row comes from `term`, which defaults to the duration as an approximation), `credit_spread_requirement` (Tables 4F-II/III, Appendix 4K classes), the discounted cash flow versions `dcf_interest_rate_requirement` / `dcf_credit_spread_requirement` (para 4.3.3.2 b), Guideline 4.14: each cash flow takes its own Table 4E row on the base curve; asset credit spreads and liability MA/IP spreads are discounted but not shocked; annual compounding; helpers `present_value`, `curve_rate` (flat or interpolated), `bond_cash_flows`, `duration`, `scale_to`), `property_requirement`, `fx_forward_exposure` + `default_requirement` (Table 4H, Appendix 4H), `misc_requirement`, and `aggregate_c2` (Tables 4C-I/II by dominant rate scenario, market vs default at 0.5, Euler contributions). Change a limit or factor in `calculator.py` → update `calc_test.py`, whose part 2 includes MAS's own worked figures (Guideline 4.12C equity 387.3, Appendix 4B 47%) as the strongest checks.
- **`app.py`**: `build_agent` is wrapped in `st.cache_resource` (restart the app after changing `SYSTEM_PROMPT`). Each session gets a uuid `thread_id`. A missing key shows `st.error` instead of crashing. UI: a CSS block styles a gradient header (frog embedded as base64), welcome question cards (`st.container(key="starters")`, shown until the first question), and chat cards. `render_answer()` HTML-escapes the reply (it is shown with `unsafe_allow_html`) and `$`, turns `**Requirement (must):**` / `**Guideline (should):**` / `**Information:**` into coloured badges, replaces the trailing "Sources:" line with chips for retrieved passages whose page is cited, and lists the passages in an expander. The sidebar "Search in" filter is passed as `Context(notice=...)`; `search_notices` reads it via `ToolRuntime` and it overrides the model's own `notice` argument.
- **Answer format**: every rule-bearing point is typed **Requirement (must)** / **Guideline (should)** / **Information** and carries a word-for-word quote with its label, so must/should can't be lost in paraphrase. `SYSTEM_PROMPT` and `answer_test.py` state the same rules; keep them in sync.
- **`answer_test.py`** skips the agent and calls the model once with `with_structured_output(Answer)`, where each point has `type`, `quote`, `source`, `explanation`. `check()` flags quotes not found word for word in the retrieved passages (ignoring line breaks, curly quotes and footnote digits; `...` or a line break in a quote marks skipped text) and types that don't match the quote's wording (`BINDING`). Its `covered=false` should come back for off-topic and out-of-corpus questions (e.g. MAS Notice 126). `SCENARIOS` run multi-turn conversations through the real agent and regex-check each reply for key facts (FX + asset concentration: 70m exposure, 8.4m, 60m adjustment, deducted from financial resources; unstated fund type (no mention of offshore) and push-back to the excess method: 7.92%, 60m kept; "after concentration adjustments": 7.92%, 60m). The expected adjustments follow `FX_ADJUSTMENT_METHOD`: change them if it changes. Write number regexes with `(?!\d)` rather than a trailing `\b`, since "8.40m" has no word boundary after the 0. `--model` compares another model (writes `answers_<model>.docx`); `--scenarios-only` skips the one-shot questions. Answers vary run to run, so run scenarios more than once before drawing conclusions.
